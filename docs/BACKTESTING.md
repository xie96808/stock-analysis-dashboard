# 回测模块可行性与实施边界

## 当前实现

日线单标的 MVP 已落地：均线交叉、价格突破和 MACD 交叉策略，下一交易日开盘撮合，A股 T+1/整手/停牌与涨跌停约束，费用和滑点，以及资金曲线、风险收益与逐笔成交输出。

## 结论

现有工程已经具备单标的日线回测所需的基础：A/H 股代码解析、前/后/不复权行情、指标计算和可视化。建议先实现“规则式、单标的、日线”回测，不直接从分钟级、多标的组合或任意 Python 策略起步。

## 最小可用版本

- **策略模板**：均线交叉、价格突破、MACD 交叉；参数可编辑。
- **信号规则**：使用当日收盘数据生成信号，默认下一交易日开盘成交，避免未来函数。
- **市场约束**：A 股 T+1、100 股一手、涨跌停/停牌时无法成交；港股按每手股数配置。
- **费用模型**：佣金、最低佣金、印花税、过户费、滑点均显式展示并可配置。
- **输出**：资金曲线、基准曲线、交易清单、最大回撤、年化收益、夏普、胜率和盈亏比。
- **复现性**：保存策略、参数、行情截止时间、数据源和引擎版本，并允许导出 JSON/CSV。

## 关键数据约束

1. 回测使用的历史行情必须固定快照；免费公网源不应在相同回测中途悄然补写历史。
2. 交易信号可使用前复权价格，但成交、手续费和持仓估值需要采用一致且可解释的价格口径。
3. 当前行情接口适合个人研究，不包含完整的退市股、指数成分历史和逐笔成交；因此首版结果应定位为策略研究，而不是机构级仿真。
4. 分钟级回测需要更稳定、可追溯的分钟历史源，并显式模拟午休、集合竞价和涨跌停排队，暂不纳入首版。

## 推荐架构

```text
strategy definition -> signal engine -> execution simulator -> portfolio ledger
        |                    |                  |                    |
        +------ snapshot metadata / audit trail / metrics ---------+
```

- 后端新增 `backtest/engine.py`、`backtest/strategies.py`、`backtest/metrics.py`。
- API 提供创建任务、查询结果和导出交易清单；任务输入包含股票、区间、复权、费用与策略参数。
- 前端增加独立“回测”页，图表叠加买卖点，下方展示指标卡、资金曲线和交易表。
- 纯函数策略与撮合规则先做单元测试，再使用固定行情夹具做黄金结果测试。

## 分阶段实施

1. **日线单标的引擎**：三种模板策略、费用、T+1、固定夹具与结果导出。
2. **研究体验**：参数扫描、与沪深 300/恒生指数比较、从主图选区启动回测、将结果附加到研究记录。
3. **数据能力升级后**：分钟级、组合仓位、再平衡、批量股票池和走样本外验证。

## 开发前需要确定

- 首个模板优先做均线交叉、突破还是 MACD；
- 仅规则表单，还是同时开放本地 Python 策略插件；
- 首版只做 A 股，还是 A/H 股共同支持；
- 默认基准、初始资金和费用参数。
