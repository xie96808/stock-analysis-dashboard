# 后续亮点功能可行性报告

## 结论与推荐顺序

| 优先级 | 功能 | 可行性 | 估算 | 主要价值 |
|---|---|---:|---:|---|
| 1 | 复盘播放/时间机器 | 高 | 5–8 天 | 让历史判断与后续走势逐日揭晓，最适合现场演示 |
| 2 | 全市场条件扫描器 | 高 | 7–12 天 | 从“看一只股票”升级为“发现机会” |
| 3 | 组合级回测与对比 | 高 | 8–15 天 | 检验多个标的、基准和资金分配 |
| 4 | 参数寻优与稳健性热力图 | 中高 | 8–12 天 | 避免只展示一个偶然最优参数 |
| 5 | 事件/财报/分红日历叠加 | 中高 | 5–10 天 | 把技术形态与基本事件放在一张时间轴 |
| 6 | PWA 与真正浏览器本地存储 | 高 | 4–7 天 | 手机安装、离线打开、个人数据不依赖服务器共享库 |
| 7 | 策略 DSL/可视化规则搭建器 | 中 | 15–25 天 | 用户无需改源码即可表达策略 |
| 8 | 可选跨设备同步/协作分享 | 中 | 15–30 天 | 多设备与朋友协作，但会引入账号、权限和隐私复杂度 |

## 1. 复盘播放/时间机器

**方案**：在当前 K 线序列上增加可移动截止日期；每次只向图表暴露截止日及以前的数据，同时加载该日研究日志、画线、筹码估算和提醒状态。支持逐日、逐周播放和“揭晓下一根 K 线”。
**复用能力**：现有 `historicalCutoff`、日志 revision、图表金融坐标和分时入口。
**风险**：必须严格隔离未来数据，指标、筹码和成交量分布都需基于截断后的数组重新计算。
**验收**：播放至日期 T 时，页面任何数值都不得读取 T 之后的数据；恢复实时视图后原工作区不变。
**建议**：优先开发，展示效果和产品独特性最高。

## 2. 全市场条件扫描器

**方案**：夜间批量获取本地索引中的日线数据，后端定时计算趋势、突破、量价、MACD、筹码集中等信号；前端提供可保存筛选器和结果表。
**数据**：优先收盘后批处理，避免对公开接口做高频并发；增量更新 SQLite/Parquet 缓存。
**风险**：10,000+ 标的的数据源限速、退市/停牌/复权一致性和任务失败恢复。
**验收**：扫描结果可追溯到数据日期、公式版本和源数据；重复运行结果确定。
**建议**：先支持自选池/300 个标的，再扩至全市场。

## 3. 组合级回测与对比

**方案**：在现有单股事件驱动回测器上增加统一交易日历、现金共享、仓位上限、调仓频率和基准；输出组合净值、回撤、相关性、行业/标的贡献。
**风险**：停牌日对齐、幸存者偏差、成分股历史、现金和交易成本。
**验收**：相同输入可复现；单标的组合应与当前单股回测一致；资金守恒。
**建议**：先做用户自选池等权/风险平价，再接指数历史成分。

## 4. 参数寻优与稳健性热力图

**方案**：后台并行运行参数网格，展示收益/回撤/夏普二维热力图；加入滚动样本外验证和 Walk-forward。
**风险**：计算量和过拟合。
**验收**：明确训练/验证区间；不只返回最优点，还展示邻域稳定性和交易数量门槛。
**建议**：组合回测之后开发，并限制任务并发与网格大小。

## 5. 事件日历叠加

**方案**：统一事件模型 `{symbol,date,type,title,source}`，在主图增加可开关标记；支持财报、分红除权、停复牌和用户自定义事件。
**风险**：可靠免费数据源、历史事件修订和港股字段差异。
**验收**：每个事件显示来源和抓取时间；事件层关闭不影响主图性能。
**建议**：先做公司行动和用户自定义事件，新闻情绪后置。

## 6. PWA 与浏览器本地数据

**方案**：静态壳与标的索引由 Service Worker 缓存；用户日志、画线、自选、提醒迁移到 IndexedDB，可导出加密或普通 ZIP。在线行情仍由 API 代理。
**风险**：现有 SQLite 与浏览器 IndexedDB 的双实现和迁移策略。
**验收**：无网络时能打开最近查看的标的、日志和画线；清除站点数据前给出导出提醒。
**建议**：如果个人网站无需多人共享，这是部署后最重要的架构升级。

## 7. 策略 DSL/规则搭建器

**方案**：先定义受限 JSON AST，如 `cross(ma(close,5),ma(close,20))`，再提供可视化积木；后端解释执行，不运行任意代码。
**风险**：表达能力、错误提示、未来函数和安全边界。
**验收**：静态检查未来引用；同一 AST 在提醒、扫描和回测中语义一致。
**建议**：不要直接开放 Python/Pine 任意执行，先做安全 DSL。

## 8. 同步与协作

**方案**：可选账户、加密同步、只读分享链接、评论；个人模式仍保持无账号。
**风险**：认证、租户隔离、数据删除、备份、隐私和运维成本最高。
**验收**：服务器端强制用户隔离；分享默认只读且可撤销；端到端审计。
**建议**：等单用户产品稳定并出现明确协作需求后再做。

## 架构建议

1. 保持图表计算为纯函数，新增功能优先复用同一指标/撮合语义；
2. 大批量任务使用后台作业队列，不阻塞 FastAPI 请求；
3. 引入数据版本号、公式版本号和可复现运行清单；
4. 前端把回测、日志、模拟面板进一步动态拆包；
5. 每个亮点功能先建立无未来函数、资金守恒、数据隔离和 crash 压力测试。
